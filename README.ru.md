# 🌅 Flow — Календарь планирования по циркадным ритмам

**Планируйте день вокруг своей энергии, а не вокруг часов.**

Мобильный планировщик, который делит сутки на **4 циркадных блока** по вашему времени подъёма и отбоя,
взвешивает каждую задачу в **когнитивных баллах** и не даёт вам перегрузить день.

## 📊 Статус — что реально работает

Flow активно разрабатывается и работает **полностью на клиенте**: без бэкенда и без телеметрии.
Эта таблица — честный источник правды: она синхронизирована с кодом, а не с пожеланиями.

| Область | Статус | Детали |
|---|---|---|
| Циркадные блоки (Утро / День / Вечер / Ночь) | ✅ | Считаются от `wakeUpTime` → `restTime`, активное окно делится на три части |
| Веса задач **Quick 1 / Focused 3 / Deep 6** | ✅ | Определяются автоматически по названию (ключевые слова + длина) |
| Ёмкость **12 баллов на блок** + авто-перенос | ✅ | `adjustTaskPeriods()` переносит перегруз в следующий свободный слот и показывает snackbar |
| Recovery Mode и Wind Down | ✅ | Дни восстановления (по умолчанию сб/вс) + последние 90 минут до `restTime` |
| 4 вида календаря (День / Неделя / Месяц / Год) | ✅ | Переключаются тапом и голосом |
| День: сетка блоков ⇄ список, сворачивание, быстрое добавление | ✅ | |
| Голосовое управление (RU / EN / ES) | ✅ | Web Speech API, браузеры на Chromium — см. [Голосовое управление](#-голосовое-управление) |
| Мягкий будильник: 7 эмбиент-звуков, fade-in, snooze 5 мин | ✅ | Звуки стримятся с `mixkit.co` |
| Светлая / тёмная тема M3 с сохранением | ✅ | Через классы `.light` / `.dark`, полностью на токенах |
| Язык интерфейса EN / RU / ES | 🟡 | Почти готово: дни недели в виде «Месяц» захардкожены по-английски |
| Повтор задач (ежедневно / неделя / месяц / все блоки) | 🟡 | Значение сохраняется в задаче, но повторные экземпляры **не** создаются |

## 🚀 Быстрый старт

**Требования:** Node.js **20+** (проверено на 24.13.0) и npm 10+. Vite 6 официально не поддерживает Node 18.

```bash
git clone https://github.com/denzakh/flow.git
cd flow
npm install
npm run dev
```

Открывайте **http://localhost:3000** — dev-сервер слушает `0.0.0.0`, поэтому приложение доступно и с телефона
в той же Wi-Fi сети (удобно проверять реальные touch-таргеты и голосовой API).

> Настраивать ничего не нужно: ни `.env`, ни API-ключей, ни базы данных. Приложение сразу открывает демо-экран
> авторизации — выберите *Guest* или любой вариант входа.

## 🧬 Циркадная модель

Всё в Flow выводится из двух чисел, которые вы задаёте один раз: **время подъёма** и **время отбоя**.

```
restTime ──────────────────────────────▶ wakeUpTime
  │        активное окно               │
  │  ┌────────────┬────────────┐       │
  │  │   Утро     │   День     │       │  Ночь
  │  │  1/3 дня   │  1/3 дня   │ 1/3   │  (восстановление,
  │  │            │            │ Вечер │   без ёмкости)
  └──┴────────────┴────────────┴───────┘
```

- **4 блока** — `Morning`, `Afternoon`, `Evening` делят бодрствующее окно на три равные части, `Night` замыкает
  цикл. Реализация: [`src/services/circadian.ts`](src/services/circadian.ts) → `getDynamicBlocks()`.
- **Wind Down** начинается за 90 минут до `restTime` и автоматически переводит приложение в Recovery Mode.
- **Recovery Mode** включается в дни восстановления (по умолчанию суббота и воскресенье) и во время Wind Down:
  показывается баннер с советом и визуалы становятся спокойнее.
- **Проверка сна:** расписание с интервалом между `restTime` и `wakeUpTime` меньше 7 часов не сохраняется —
  выводится локализованная ошибка.
- **Активный блок** пересчитывается каждую секунду по тикающим часам (`currentTime`), поэтому интерфейс всегда
  понимает, в какой части суток вы находитесь.

### Веса задач и ёмкость в 12 баллов

| Вес | Баллы | Как определяется по ключевым словам (RU/EN) |
|---|---|---|
| ⚡ Quick | **1** | `почта`, `звонок`, `оплатить`, `купить`, `убрать`, `заказать`, `email`, `call`, `buy`, … |
| 🎯 Focused | **3** | *по умолчанию*, если ничего не совпало |
| 🧠 Deep | **6** | `код`, `дизайн`, `исследование`, `рефактор`, `тест`, `стратегия`, `study`, `design`, … |

При равенстве срабатывает эвристика длины (≤ 20 символов → Quick, ≥ 50 символов → Deep). См.
[`suggestWeight()`](src/services/taskOptimizer.ts).

- **В блок помещается 12 баллов.** Карточка блока показывает шкалу заполнения и дополнительную янтарную рамку,
  когда блок переполнен.
- **Перегруз — это не наказание, а перенаправление.** Если задача не помещается, `adjustTaskPeriods()` ищет
  следующий свободный слот (позже в дне → завтра) и сообщает, куда задача попала
  ([`src/utils/taskCreation.ts`](src/utils/taskCreation.ts) → `resolveTaskPlacement()`).
- Блок **Ночь** не принимает новые задачи и не участвует в расчёте ёмкости — это зона отдыха, а не слот.
- **Приоритет** кодируется формой, **вес** — размером и цветом, см.
  [`src/components/ui/TaskBubble.tsx`](src/components/ui/TaskBubble.tsx) (круг / squircle / 12-гранное «печенье»).

## 🎤 Голосовое управление

Нажмите на микрофон в нижней панели и говорите. Всё работает на правилах (регулярные выражения + контекстный
анализ) — никаких LLM в контуре.

| Интент | English | Русский |
|---|---|---|
| Добавить задачу | “add task call the bank”, “remind me to buy coffee” | «добавь задачу позвонить в банк», «напомни купить кофе» |
| Выполнить | “complete task 2”, “done with the report” | «выполни задачу 2», «готово» + название |
| Удалить | “delete task 3” | «удали задачу 3» |
| Сменить вес | “make task 1 deep” | «сделай задачу 1 глубокой» |
| Перенести в блок | “move task 2 to evening” | «перенеси задачу 2 на вечер» |
| Сменить приоритет | “mark task 1 high priority” | «сделай задачу 1 важной» |
| Навигация | “next day”, “go to today”, “what's due tomorrow” | «следующий день», «сегодня», «что завтра» |
| Сменить вид | “show week view”, “open month” | «покажи неделю», «открой месяц» |

- **Языки:** английский, русский, испанский (`en-US` / `ru-RU` / `es-ES`).
- **Порог уверенности:** если уверенность распознавания ниже порога (по умолчанию `0.7`), команда показывается
  в диалоге подтверждения, а не выполняется. Нулевая confidence подменяется на `порог + 0.1`.
- **TTS-обратная связь:** после выполнения команда проговаривается вслух (голос выбирается в Настройках → Голос).
- **Фильтр шума:** приветствия и слова-паразиты (`привет`, `ok google`, `hola`, …) никогда не становятся задачами.
- **Fallback-правило:** любая нераспознанная фраза трактуется как «добавить задачу» — так диктовка «просто работает».
- Код: [`src/services/voice/`](src/services/voice) — `VoiceControlService.ts` (STT/TTS),
  `VoiceCommandProcessor.ts` (нормализация, фильтр шума, извлечение сущностей) и `commands/` (паттерны).

## 🏗️ Архитектура

### Гибридный UI: две системы, один источник токенов

Приложение намеренно смешивает два мира стилизации. Правило (оно же зафиксировано в
[`.clinerules`](.clinerules)):

- **Standard UI** — модалки, шторки, формы, настройки, тулбары, snackbar'ы → **Material UI**,
  темизация **только** через [`src/theme/mui-theme.ts`](src/theme/mui-theme.ts), который пробрасывает
  CSS-переменные в палитру MUI.
- **Expressive UI** — циркадные блоки, баблы задач, слой дат → **Tailwind CSS v4** плюс CSS-переменные.
  MUI-обёртки здесь запрещены: они ломают DOM-структуру этих кастомных элементов.

### Дизайн-токены — единый источник правды

```
src/theme/tokens.css        ← SSOT: ~800 переменных M3 + расширения Flow, блоки .light и .dark
        │
        ├── src/theme/mui-theme.ts   → палитра / типографика / формы MUI (var(--md-sys-color-*))
        ├── tailwind.config.ts       → утилиты (bg-surface-container, text-primary, rounded-md-lg, …)
        └── компоненты               → inline style={{ background: 'var(--flow-block-morning)' }}
```

Правила, которых держится код (и которые должен проверять ревьюер):

- **Никаких хардкод-hex** в компонентах и никаких пикселей в `sx` для лейаута — только `var(--…)` или Tailwind.
- Спатинг лейаута → Tailwind; `sx` оставлен для внутреннего состояния компонента (размер, радиус, цвет).
- Только M3-кривые движений: `ease-m3-emphasized` / `ease-m3-decelerate`. Ни `linear`, ни `ease-in-out`.
- Тач-таргеты ≥ 48–52 px — этому следуют все иконочные кнопки приложения.
- Перегруз показывается **янтарным** (`--flow-capacity-overload`), красный запрещён.

### Порядок слоёв (z-index)

| Слой | Содержимое |
|---|---|
| Фон | градиент, световые пятна, тематическая картинка |
| Контент | `Header` → `ViewSwitcher` → виды День/Неделя/Месяц/Год → `FlowToolbar` |
| Темпоральный | `DateNavigator` (назад/вперёд + дата) под видом, над тулбаром |
| Оверлеи | шторка задачи, настройки, модалка будильника, подтверждение голоса, snackbar ёмкости |
| Тулбар | `FlowToolbar` — фиксированная нижняя панель (настройки, идеи, микрофон, добавить, смарт-планировщик) |

### Состояние и поток данных

`App.tsx` — единственный владелец состояния: `tasks`, `settings`, `voiceSettings`, `viewMode`, `viewDate`,
`collapsedBlocks` плюс секундный тик `currentTime`. Производные значения (`activePeriodId`, `dynamicBlocks`,
`isRecoveryMode`, `isWindDown`) мемоизируются от этого тика. Все мутации идут через несколько обработчиков
(`commitTask`, `toggleTask`, `updateTask`, `deleteTask`, `executeVoiceCommand`) и зеркалятся в `localStorage`.
Стора, сервера и разрешения конфликтов пока нет.

| Safari (macOS / iOS) | ✅ | ⚠️ частично, зависит от языкового пакета ОС |
| Firefox | ✅ | ❌ `SpeechRecognition` не реализован |

Прочие требования рантайма: `localStorage`, а также доступ в сеть для шрифта Google Fonts и mp3 будильника.
Будильник выходит на полную громкость за 15 секунд — это осознанный анти-шоковый сценарий; учитывайте, что браузеры
блокируют автовоспроизведение до первого взаимодействия пользователя со страницей.

## 🤝 Как участвовать в проекте

1. Ветка от `main` (`feature/…`, `fix/…`), коммиты сфокусированные — история следует
   [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `chore:`).
2. Прочитайте [`.clinerules`](.clinerules) (или [`docs/ui-rules.md`](docs/ui-rules.md)) **до** правок UI.
   Необсуждаемое: токены вместо hex, `lucide-react` вместо иконок Material, Tailwind для лейаута,
   M3-easing, тач-таргеты ≥ 48 px, `onPress` вместо `onClick` в expressive-компонентах.
3. Новые токены сначала едут в [`src/theme/tokens.css`](src/theme/tokens.css) (и в `.light`, и в `.dark`),
   и только потом пробрасываются через `mui-theme.ts` / `tailwind.config.ts`.
4. Проверьте, что `npm run build` проходит, и вручную пройдите затронутый сценарий в обеих темах.
5. Обновляйте затронутую документацию (`CLAUDE.md`, `TEST_PLAN.md`, `docs/…`) в том же коммите — документация
   часть продукта.
